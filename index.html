変換キーの誤発火を修正した
32 打鍵 · Space 0

Windows 用のかな漢字変換 IME。打鍵に追随して変換が進むライブ変換と、確定した瞬間に半角英数へ戻る一時日本語モードで、「モードを切り忘れる」という状態そのものをなくす。変換も学習もこの PC の中で完結する。

日本語 IME が、開発者につらい理由

コマンドが全角で入力されてしまった例。

$ ｇｉｔ　ｓｔａｔｕｓ
command not found

普段は半角英数のまま。F8 で入った日本語は、確定した瞬間に英数へ戻る。切り忘れという状態が存在しない。

セミコロンが全角になってしまった例。

error: expected `;`, found `；`

日本語モードの最中でも、記号は半角のまま入る。全角にしたければ設定で選べる。

議事録を取っていると、変換と確定の合いの手で手が止まる

ライブ変換は候補を出すだけでなく、確定まで自動で進む。

打てば、こうなる

そのまま打ち続ける
ライブ変換 — 打鍵に追随して変換が進み、確定まで自動。従来の Space 変換もそのまま使える
F8
一時日本語モード — 確定した瞬間に半角英数へ復帰する
選択して 変換
モードレス再変換 — 半角英数で打ったローマ字を、あとから日本語にする
Tab
修正変換 — 「こんんいちは」を修復。誤読みごと学習し、次からは通常の変換で直る
Shift + 英字
文中に英単語をそのまま混ぜる
(opt-in)
Zenzai — GGUF モデルを置くと、文脈を読む変換がローカル CPU で動く。無ければ古典 LOUDS 変換

キーは設定 GUI ですべてリバインドでき、衝突は保存時に検出される。起動時から半角英数で始める設定もある。

IME は、あなたが打つすべてを見ている

  • 入力内容・変換履歴・テレメトリ・クラッシュレポートのいずれも送信しない。クラウド変換 API は存在しない。
  • 変換も学習も、古典 LOUDS もニューラル(llama.cpp / CPU)も、この PC の中だけで動く。
  • パスワード欄では変換も学習もしない。
  • 全コードを公開している(MIT)。TSF 層は Rust、変換エンジンホストは Swift。

PRIVACY.md / SECURITY.md

入れる

  1. Releases から nospacekey-setup-1.1.0-devsigned.exe を取得する。
  2. 実行する。IME の登録はマシン単位のため管理者昇格を求められる。開発用の自己署名なので SmartScreen の警告が出る —「詳細情報」→「実行」で続行できる。
  3. Win + Space で「nospacekey」を選ぶ。
> Get-FileHash .\nospacekey-setup-1.1.0-devsigned.exe -Algorithm SHA256

出力を、リリースに添付された SHA256SUMS.txt と照合できる。

変換エンジン AzooKeyKanaKanjiConverter、モデル zenz-v3.1-small、推論に llama.cpp を使っている。azooKey とは独立した非公式プロジェクトで、不具合や質問は 当リポジトリの Issue へ。
